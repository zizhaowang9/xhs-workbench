# Bridge 启动修复：1.1.2

## 现场问题

1.1.1 的 Windows 运行入口传入 `--root <安装目录>`，但随包的 `bridge_server.py` 仅声明 `--port`。Python 因未知参数退出，退出码为 2。端口占用处理完毕后仍无法启动，原因在程序文件之间的接口不一致。

## 最小修复

- 在现有服务端增加可选 `--root`，保留原有 `--port` 用法和 localhost 监听。
- `ping_server` 保留扩展状态字段，补充安装根、实际进程和服务脚本路径；旧启动方式仅在已知安装目录结构和路径配置存在时推导安装根。
- Windows 进程命令行先分离解释器，再识别脚本完整路径；不再把两条路径拼接成一个目录。
- 复用已有 Bridge 时核对服务响应；无法确认归属或其他安装目录仍停止本次启动，不结束其他进程、不换端口。
- 运行入口返回服务进程的实际退出码。新增 `-NoPause` 仅用于自动检查，普通双击仍保留窗口提示。
- 安装与更新的本地自检检查服务端是否支持启动器参数，不启动端口、不访问账号。

这是对 `autoclaw-cc/xiaohongshu-skills` 基线 `b043748282a57e347c52f517dfb59819121134ab` 的本地兼容补丁。依赖锁文件和图片渲染器未改动。

## 回归入口

- `tests/bridge_smoke.py`：真实本地 WebSocket 子进程，覆盖显式安装根和旧启动方式。
- `tests/bridge_windows.ps1 -Root <隔离安装根>`：实际 Windows 运行入口、中文空格路径、状态和归属检查、重复启动复用、失败退出码；另有明确标为本地替身的路径解析边界检查。
- `tests/windows_smoke.ps1 -Install`：在独立目录安装后调用上述检查。测试不连接浏览器扩展、不调用模型、不操作小红书。

## 已安装用户

1. 在没有出稿任务运行时，关闭已经退出的 Bridge 错误窗口。
2. 双击实际安装目录中的 `更新工作台.cmd`，确认版本为 `1.1.2`，已拉取提交和已成功应用提交一致。
3. 双击同一安装目录的 `启动助手.cmd`，保留 Bridge 窗口。
4. 双击 `检查环境.cmd` 核对 Bridge、扩展和登录状态。

实际同事电脑上的扩展连接、登录及真实草稿仍以现场检查为准。localhost 自动检查通过不代表账号工作流已经通过。
